      How it works

      The story

      Hester, the innkeeper, greets you by the name you typed (or asks for it) and writes it in her ledger, then fetches Old Bram, who tells the story. Both are LiveKit agents (npm run agent) using LiveKit Inference for speech and the LLM. Only one player is heard at a time: Old Bram gives each a turn. Open a second tab to play with two voices, or add Pixel, a mute scripted player whose gestures Old Bram weaves into the story.

      Soundtracks

      At each new scene this app pulls a soundtrack into the room with LiveKit's Ingress API. The soundtrack's volume slider only changes what you hear.

      Webhooks

      LiveKit sends every room event (people joining and dropping, tracks, soundtracks starting and ending, the room finishing) to a Hookdeck source. Hookdeck delivers them to this app through hookdeck listen, deduplicates repeats on the event id and retries failed deliveries. The app verifies each webhook's signed token with LiveKit's WebhookReceiver.

      Session chronicle and calls

      Both are built only from the webhooks this app receives. Players, the story agent and soundtracks are told apart by the participant kind in each payload.

      Failure injection

      Make this app fail or answer slowly. Hookdeck keeps each event and retries it until the app answers 2xx, so LiveKit is never kept waiting.

      Webhook deliveries

      Every request that reached this app, newest first. A repeated event id is a duplicate delivery and doesn't change the log. Watch each one arrive in the Data flow pane at the bottom of the page.
